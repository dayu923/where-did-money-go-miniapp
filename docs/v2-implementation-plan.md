# 「钱去哪里了」V2 实施方案

> 状态：分阶段实现中。2026-11-23 已接入不含个人账单的产品介绍笔记入口，待小红书容器验证；AI 聊天、账本问答和原生分享仍未实现。  
> 目标：把产品从「带有语音输入的记账工具」升级为「以对话完成记账、查账和复盘，并能由用户主动分享」的小红书小工具。

## 1. 产品目标

V2 的主体验是聊天。用户用自然语言记录收支、查询真实账本、理解预算和消费变化；传统表单与账单列表继续作为可编辑、可核对的底层工具。AI 负责理解和解释，账单金额、分类统计、预算和结余仍由本地业务代码计算，账单写入仍须用户确认。

核心闭环：

**对话记账 → 核对账单 → 看懂变化 → 设置预算/目标 → 自主分享**

V2 不接银行卡、不接支付账户、不自动发布笔记、不在未经用户明确同意时将账本明细传给模型。

## 2. 官方能力核对（2026-11-21 在线文档）

本方案根据 [小红书小工具在线文档](https://miniapp-sandbox.xiaohongshu.com/minitool/doc) 当前公开内容制定。实施时仍须用对应版本 Skill 和在线文档复核。

### 平台 AI 对话

- 通过 `window.xhs.AI.createModel(...).generateText(...)` 使用平台模型，不需要在包内放 API Key 或自建模型地址。
- 在线文档标为内测：需平台为目标 `appId` 加白；未加白时会返回 `AI_NOT_ALLOWED`。创服页的「AI 对话能力」也须按平台要求开启。
- 当前为非流式生成；文档列出 `deepseek-v4-flash`、`dots-3-note-prev`，每次最多 40 条消息、总计 12,000 字符，最大输出 2,048 tokens；内测期每位用户每天最多 100 次调用。
- 平台不保存对话上下文；调用方需裁剪并传入消息历史。内容可能被平台审核；必须处理空 `choices`、配额耗尽、内容拦截和能力不可用。
- 文档没有说明账单数据的留存、处理区域或模型侧使用范围。接入前必须确认平台数据处理说明，并向用户清楚说明哪些输入会交给平台 AI。未确认前不把整本账单、备注或完整历史发给模型。

### 发布笔记 `postNote`

- `window.xhs.miniTool.postNote(...)` 唤起小红书笔记编辑/发布流程，带入标题、正文和媒体；用户可以继续编辑、取消，并由用户主动发布。
- 这不是后台自动发布，也不能据调用成功判断笔记审核或发布结果。
- `mediaInfo` 至少包含一种媒体。图文可传 1–18 张包内图片、本地文件路径或 `data:` 图片；标题最多 20 字、正文最多 1,000 字。视频和实况照片另按在线文档要求提供。
- 不通过外网地址加载图片；统计卡片由包内 Canvas 2D 生成，或以平台认可的本地文件路径传入。

### 分享 `miniTool.share`

- `window.xhs.miniTool.share({ type: "card" })` 拉起小工具卡片分享面板；身份由容器提供，无需传 appId。
- `type: "image"` 可传本地图片或 `data:` 图片，但文档限定此图片用于站内私信；站外渠道使用平台生成的小工具页面截图，不把 `image_resource` 当作站外海报。
- 需要全屏容器及客户端 9.53+；每位用户每天每个小工具最多拉起 10 次。调用返回只代表分享操作已启动或用户取消，不代表最终送达。
- 能力缺失、半屏容器、低版本、重复调用、素材错误和频控都要有清晰降级；分享不可用不影响记账。

### 可选能力：评论草稿

`interactionOpenApi`（客户端 9.49+）可携带文本/图片打开评论编辑器。它不是通用分享接口，也不应把财务明细自动贴进公开评论。首版 V2 暂不接入，只有用户验证了明确场景后再评估。

### 平台赞赏 `rewardAuthor`

- 当前在线文档将该 API 标为内测能力，最低客户端版本为 9.53.3（iOS / Android）；先在创服开通当前小工具的赞赏能力。
- 本地集成使用发布期开关 `data-xhs-reward-enabled`，默认关闭；确认创服已开通后再将其设为 `true`。在线文档未提供可在运行时读取赞赏发布配置的 JS API。
- 入口只在发布期开关开启、客户端版本满足要求且 `rewardAuthor` 方法存在时显示；触发必须由用户主动点击。
- 回调不包含赞赏金额或支付状态，界面不得宣称已收款。失败或用户取消均给出中性反馈。

## 3. V2 功能范围与优先级

### P0：聊天式真实记账

1. 首页改为聊天主界面；底部导航建议为「聊天、账单、统计、我的」。保留手动记账作为随时可用的备用入口。
2. 支持自然语言新增收入/支出，例如「午饭28块」「昨天打车32元」「今天收到工资8000元」。
3. AI 结果先形成待确认账单卡片，展示类型、金额（元）、分类、日期、备注和原文。用户可编辑字段后确认保存，或取消；取消不产生任何账单。
4. 缺少金额、多个金额、日期或分类不清楚时先追问，不能猜测后保存。重复提交需防重。
5. 语音继续作为可选输入：环境支持时由用户主动启动；不支持时可粘贴手机输入法语音转写或键盘输入。识别文本与 AI 回复均不得直接触发账本写入。

### P0：基于真实账本的对话查询

- 支持「这个月餐饮花了多少」「本周比上周多花在哪」「离月预算还差多少」等问题。
- 先由本地统计服务按所选月份/分类计算数字，再将最少必要的聚合结果交给 AI 组织解释；账单明细默认不发送。
- 回答附带统计周期和可点击的账单/分类入口。无数据时明确说没有记录，不补造金额、类别或趋势。
- 账单问答不可用、AI 失败或返回无法解析时，给出普通统计页面/筛选列表作为替代，不篡改账本。

### P1：对话式预算和存钱目标

- 通过待确认卡片设置/调整月预算、分类预算和存钱目标；用户确认后调用现有本地服务保存。
- 支持查询预算余额、预算使用情况和目标进度；收入不计入支出预算。
- 不主动输出投资、借贷或诊断类建议；复盘保持描述事实和温和提醒。

### P1：小红书笔记发布

- **已实现的 V2 切片（待容器验证）：**「我的」页提供「发布笔记」入口，使用本地 Canvas 生成产品介绍图片并调用 `postNote`，不传账单数据；用户在小红书发布页检查并决定是否发布。
- 在统计页或聊天总结中提供「生成分享笔记」入口，不默认自动生成或打开发布流程。
- 提供两类模板：不含个人金额的记账/存钱心得模板；用户主动选择后生成的个人月度复盘卡片。
- 生成前展示预览、标题、正文、将包含的数据项和「继续到小红书编辑器」按钮。用户可以取消或修改；只有用户再次点击后才调用 `postNote`。
- 初版只生成一张本地 PNG 统计卡片，并用 `pageType: "photo_publish"` 和 `mediaInfo.image_resources` 唤起编辑器。模板中的统计值来自用户明确选择的周期，生成前再次核对；不包含账单备注、商户名或其他敏感细节。
- 容器 API 缺失/失败时说明无法打开发布页，保留用户可复制的纯文本草稿；不得声称已经发布。

### P1：分享小工具与分享卡片

- 「分享给朋友」优先使用 `share({ type: "card" })` 分享小工具卡片。
- 另提供可选的站内私信图片分享：仅分享用户预览并确认过的总结卡片，使用本地 Canvas PNG / `data:`，不包含默认账单详情。
- 每次调用必须由用户点击触发；分享前预览内容并允许取消。记录平台返回的失败状态供界面反馈，但不把回调当作送达凭证。
- 如未来要生成站外图片，不能复用 `type: "image"` 参数宣称可发到站外渠道；须遵循平台页面截图/分享规范另行核实。

## 4. 隐私与安全规则

1. 首次使用 AI 查账或复盘前，展示说明并取得用户主动同意。说明平台 AI 会接收哪些文本/聚合数据、用途和关闭方式；关闭后仍可手动记账和查看本地统计。
2. 不发送完整账本、完整备注、用户身份信息、银行卡/支付信息或未经筛选的聊天历史。每次只传当前问题必要的分类汇总或日期汇总。
3. 不把模型输出当作可信指令；把返回结果作为纯文本显示，不使用 `eval`、HTML 插入或动态代码执行。
4. AI 拟写的账单字段先经本地校验：分类必须在允许列表，日期必须有效，金额解析为正整数分，结构不完整就追问/改手动填写。所有新增、修改、删除仍需用户明确确认。
5. 默认仅在当前页面内存保留聊天上下文。若后续确需保存历史，另做显式开关、清除入口和版本迁移；不默认永久保存 AI 对话。
6. 不打印账单全文、AI prompt 或私人对话到控制台。AI 调用失败、超额、权限未开通时不转发给第三方模型、不静默提交、不伪造成功。
7. 分享卡片默认不含金额；选择包含金额时逐项预览并再次确认。发布笔记和分享均由用户最终决定。

## 5. 技术方案

### 页面与模块

- `chat`：消息列表、快捷问题、输入框、AI 调用状态和待确认账单卡片。
- `ai-service`：检测 `window.xhs.AI` 和 `createModel`/`generateText`；封装平台模型调用、最近对话裁剪、错误码处理。只使用官方文档列出的 API，不接第三方服务。
- `intent-parser`：校验 AI 返回的记账意图；不满足 schema 时进入追问或手动编辑状态。
- `ledger-query`：调用现有 `LedgerCore` 计算聚合及日期范围；AI 不负责金额求和。
- `share-card`：Canvas 2D 绘制已确认的统计卡片，生成 PNG `data:`；核对图片有效、大小和平台要求。
- `platform-actions`：单独封装 `postNote`、`share` 的能力检测、版本检测、参数校验和错误提示。
- `storage`：沿用现有 Storage 服务与数据迁移机制；保留用户账单的 schema 不变。聊天历史不进入账单分片。

当前项目为独立经典脚本，不引入框架或联网依赖；新增脚本通过 `index.html` 顺序加载，最终 ZIP 仍须包含离线自包含资源并将 `index.html` 放在根目录。

### AI 消息策略

- 模型建议先使用官方文档推荐的 `deepseek-v4-flash`；若 `dots-3-note-prev` 更符合产品人格，再在真机对比后选择。模型名称不做未经验证的自动回退。
- 每次发送前限制消息数及字符数，保留系统规则与最近必要轮次；按在线文档上限（40 条、12,000 字符）裁剪。
- AI 调用非流式，界面显示轻量等待态；支持取消后丢弃迟到结果、输入锁定/防止重复请求。
- AI 的“记账动作”采用意图 JSON 约束提示，但接口是纯文本生成，不假设模型支持 JSON Schema、函数调用或工具调用；解析失败走可编辑表单/追问。
- 对多项操作采用一个确认卡片逐条列出，明确保存的条目数量和合计金额；不得把整段自然语言作为一笔账单备注。

### 发布和分享处理

- `postNote` 与 `share` 分开入口、分开参数与状态，不把调用成功显示成「已发布/已送达」。
- `share` 调用前检测全屏容器、`window.xhs.miniTool.share` 和客户端版本；低于 9.53 或能力不存在时隐藏/禁用入口并提供不依赖分享的统计功能。
- 对 `postNote` 调用检查 `window.xhs`、`miniTool` 和 `postNote` 方法；在线文档未给通用最低版本时不自行假定客户端版本门槛，只做方法能力检测并准备失败提示。
- `postNote` 成功后说明用户已在发布页点击发布，并引导其在小红书查看最终发布和审核状态；不将调用结果记录为最终发布成功或审核通过。
- `postNote` 失败时不假定具体取消错误码；用中性提示覆盖流程失败或用户取消，并允许用户重试。

## 6. 分阶段交付

### 阶段 A：能力与隐私预检

- 重新阅读当时 Builder Hub 在线文档和口令版本 Skill，确认 AI 内测资格、appId 加白步骤、发布页授权设置、AI 数据处理说明、目标客户端版本和审核要求。
- 用空白账本和合成数据定义 AI 请求上下文；先完成隐私文案、AI 开关和失败状态设计。
- 明确 appId/UID 由平台按官方流程配置，不将令牌或密钥写入源码。

### 阶段 B：聊天记账 MVP

- 首页切换为聊天主入口；接入 AI 文本生成和用户同意流程。
- 实现记账意图校验、追问、确认卡片、保存/取消和错误降级。
- 复用现有账单服务、账单列表和统计，不重写 V1 存储结构。

### 阶段 C：真实账本问答与预算

- 实现本地聚合查询、周期识别、分类和预算上下文最小化传递。
- 加入预算与目标操作确认卡片、账单明细跳转、AI 失败时回退统计页。

### 阶段 D：笔记与分享

- 实现本地统计卡片预览和 Canvas PNG 导出。
- 接入 `postNote`；验证发布编辑器打开、取消、编辑、用户发布的实际边界。
- 接入 `share({ type: "card" })`，再评估是否有必要增加仅站内私信的图片分享。

### 阶段 E：验证和发布

- 自动化覆盖 AI 正常/拒绝/未加白/超额/空响应/无效结构、对话裁剪、意图歧义、用户确认/取消、账单持久化与迁移、问答金额与本地统计一致、卡片图片生成、分享失败/取消、发布页失败/取消。
- 在普通浏览器只测降级路径；AI、`postNote`、`share` 必须在官方模拟器允许的范围与小红书真机环境按目标客户端验证。
- 按当时 Skill 审计 ZIP、允许文件类型、包体、资源路径和离线约束；重新生成包和预览二维码。没有用户明确送审授权时不送审。

## 7. V2 验收标准

- 新账单在对话中从输入到确认保存全程真实写入现有本地账本；AI 不可用时仍可用表单记账。
- 含糊金额、多个金额、无效日期、未知分类和模型无效文本会被追问或转入编辑状态，不会误保存。
- AI 对账回答与程序计算的账单总额一致，并能打开相应明细；无数据与调用失败均有诚实提示。
- 未授权 AI 访问账本时，AI 收到的上下文不含账单/预算内容；用户拒绝后核心本地功能仍可用。
- `postNote` 仅打开预填的发布编辑器；用户能预览、编辑、取消，产品不宣称代发成功。
- 小工具卡片和图片分享按容器/版本/频次限制降级；分享取消或失败不影响账本。
- V1 用户账单、预算和目标无损迁移；AI 请求错误不会更改或清空账本。
- 官方模拟器与 Android/iOS 真机验证结果分开记录；未测环境不宣称通过。

## 8. 暂不纳入 V2 首发

- AI 自动保存、自动删改账单、无人确认的定时操作。
- 发送整本账单给模型、跨设备云同步、第三方在线语音识别、自建外部 AI 服务。
- 公开展示真实支出、默认带金额分享、自动发布笔记、自动评论或承诺笔记审核/送达。
- AI 投资/借贷建议、排行/社交比较、付费会员和多账本。

## 9. 验收风险与待平台确认

- AI 目前标注内测，appId 加白、额度、模型清单、平台内容审核及数据处理条款均可能变化；这些是开始实现的前置条件。
- 平台 `share` 最低版本为 9.53，要求全屏容器；图片分享只用于站内私信，分享面板频次有限。
- `postNote` 唤起编辑器不代表最终发布或审核通过，用户仍需编辑和主动发布。
- AI 文本输出和自然语言统计解析仍可能出错；通过程序校验、数据最小化和用户确认控制风险，不宣称模型无误。
- 普通浏览器和 CLI 预检无法证明真机能力、模型加白、发布页流转或分享面板可用。
